Theming

Light and dark are sets of semantic token values; components never change between themes. How it works, how to add a theme and how to consume tokens.json.

Overview

Themes are sets of semantic token values. Light is the default on :root and [data-theme="light"]; dark applies with [data-theme="dark"], or automatically when the OS prefers dark and the page has not forced light. Each theme sets color-scheme so native controls and scrollbars follow.

The three tiers

TierPrefixExampleWho reads it
Primitive--palette-*, --font-size-*…--palette-gold-400: #ffb81csemantic tokens only
Semantic--color-*, --space-*, --text-*…--color-accent: var(--palette-gold-400)components and pages; themes override this tier
Component--btn-*, --field-*, --chip-*, --toast-*, --alert-*--btn-bg: var(--color-accent)one component; declared in components.css

Switching themes

<html lang="en-CA" data-theme="dark">   <!-- force dark -->
<html lang="en-CA">                     <!-- follow the OS -->
<section data-theme="light">…</section> <!-- a light region inside a dark page -->
  • The product stores the member's choice (Preferences → Appearance) and sets data-theme on <html> before first paint to avoid a flash.
  • Any element can carry data-theme; semantic colour tokens are declared on the theme selector itself, so a region resolves its own values (this site's side-by-side previews rely on it).
  • prefers-contrast: more promotes default borders and muted text to the stronger tokens; forced-colors: active hands the focus ring and borders to system colours.

Adding a theme

  • Copy the dark block, rename it [data-theme="<name>"], and override semantic tokens only. Never edit primitives in a theme and never theme component CSS.
  • Add any new pairings to tokens/contrast-pairs.json and run check_contrast.py; it reads every [data-theme] block.
  • Re-export tokens.json with tokens_to_json.py.

tokens.json

tokens/tokens.json is a DTCG export generated from tokens.css: every token has $type and $value, aliases are written as {group.token}, and dark values sit under $extensions. Use it to generate Angular/TypeScript constants or native platform values; never edit it by hand.
