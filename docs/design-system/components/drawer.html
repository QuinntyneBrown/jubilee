Drawer

A drawer is a modal panel pinned to one edge of the screen. It ships in the Jubilee kit, but no mock uses it: phone filters and the user menu are bottom-sheet dialogs. This page fixes how it should behave before anyone reaches for it.

WCAG 2.2 AAStatus: kit, unusedKit only · 0 uses in the mocksrole="dialog"

Overview

Consider a drawer when a desktop task needs a tall panel next to the content it affects, such as a filter panel on a category page or a details pane beside a conversation, and the person benefits from still seeing the page. On phones the Dialog bottom sheet already covers filters and menus, and it is what the mocks use. If the panel is the main thing on screen, make it a page.

  • Right (default, .drawer): contextual panels such as filters and details.
  • Left (.drawer--left): navigation. Jubilee's phone navigation is the Tab bar, so a left drawer should not be added without a navigation decision.

Anatomy

  1. Header.drawer__header: <h2 class="drawer__title"> (--text-h4) and a close icon button, ruled below.
  2. CloseGhost icon button with aria-label="Close".
  3. Body.drawer__body: scrolls, padding --space-6.
  4. Footer (optional).drawer__footer: ruled above, actions right-aligned, primary last.

Sizes

One width: min(100%, 28rem). On a 360px phone the drawer is full width, which is why phones use the bottom-sheet dialog instead.

States

A drawer is either closed (not in the DOM, or hidden) or open. Inside it, the footer goes busy like a dialog footer while results load. Pointer states belong to its controls.

Responsive behaviour

  • Width is min(100%, 28rem): 448px on tablets and desktops, the full screen on phones.
  • Below 640px use the bottom-sheet Dialog for the same content; it is shorter, reachable with a thumb, and what the mocks show.
  • The body scrolls; the header and footer stay put.

Theming

The panel is --color-bg-surface-raised with --shadow-4, the same as a dialog panel, over the shared --color-bg-backdrop. Rules use --color-border-default. Nothing is drawer-specific, so dark mode follows the semantic tokens.

Accessibility

Role and pattern

A modal drawer is a dialog: role="dialog", aria-modal="true", aria-labelledby → the title. Follow the APG dialog (modal) pattern; <dialog> with showModal() is the preferred build.

Keyboard

KeyAction
Tab / Shift+TabStays inside the drawer.
EscCloses the drawer; focus returns to the button that opened it.
SpaceToggles the focused checkbox.

Focus

On open, focus goes to the first control in the body (or the title with tabindex="-1" when the body starts with text). The shared ring is used throughout.

Labelling

The title names the drawer ("Filters"). The opener says what it opens and shows a count when filters are applied ("Filters, 2 applied").

Motion

Slides in from its edge over --duration-slow with --ease-enter; reduced motion zeroes it and the drawer appears in place.

Touch

Close is a 44px icon button; choices are at least 24px tall with label text widening the target; footer buttons are 44px.

Content

  • Title the drawer with what it holds: "Filters", "Request details".
  • The primary action reports the result: "Show 4 businesses", updated as boxes are ticked.
  • Offer "Clear all" when there is more than one filter.
