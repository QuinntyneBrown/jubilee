Card

A card is a white (or warm dark) surface with a hairline edge that holds one topic: request details, a settings group, a stat, a list of notifications. Most Jubilee cards are static sections; the clickable business tiles are a separate component.

Overview

Use a card to give one topic its own surface on a busy page: the Details and Progress blocks of a request, each settings group on the account page, the four numbers on the business dashboard. Do not use a card to make a page look designed; a single column of text needs no card. Clickable listing tiles are the Business card, not .card--interactive.

  • Card (.card) is a section: a heading (.card__title) and content, padding --space-6. It is the 123 card__title uses in the mocks.
  • Card with footer (.card__footer) adds a ruled action row, left-aligned for secondary actions on request detail pages.
  • List card (.card--list) is flush and holds rows that run edge to edge (notifications).
  • Well (.well) is a sunken panel inside a card or dialog for a read-only summary (the order summary in Confirm order).
  • Danger zone (.card.danger-zone) gives the destructive settings group a red edge.
  • Interactive, selected and flush cards, and .card__header, ship in the kit but are not used in the mocks; they are documented so they are used the same way when needed.

Anatomy

  1. Surface--color-bg-surface, hairline --color-border-default edge, --radius-lg, --shadow-1.
  2. Title.card__title on a real heading (h2 or h3 for the page outline), --text-h4; it names the section via aria-labelledby.
  3. ContentAnything: a description list, rows, a timeline. Padding --space-6 on every side.
  4. Footer (optional).card__footer: ruled top edge, --space-4 above and inside, actions in a row.

Variants

Pick the variant by what the content is, not by how much emphasis you want; cards never compete with the primary button.

  • Hover on an interactive card raises it to --shadow-2, strengthens the edge and lifts it 1px.
  • Loading cards are drawn with the Skeleton shapes in the same card, so the layout does not jump.
  • Selected uses aria-selected="true" only inside a listbox or grid; elsewhere the selection belongs to a radio inside the card.

Responsive behaviour

  • Cards fill their column; width comes from the layout (.split, .stat-grid, .container--narrow), never from the card.
  • Settings cards are capped at --layout-container-narrow (672px) on wide screens and run full width below it.
  • Padding stays --space-6 at 360px; a card with a footer wraps its actions onto a second row rather than shrinking them.
  • .stat-grid shows two cards per row on phones and four from 1024px.

Theming

Cards read only semantic tokens. In dark mode the surface is a warm charcoal one step above the canvas, the hairline edge carries the separation and the shadow is weaker; the well drops one step below the surface.

.card { background: var(--color-bg-surface); border: var(--border-width-hairline) solid var(--color-border-default); border-radius: var(--radius-lg); box-shadow: var(--shadow-1); }
.well { background: var(--color-bg-surface-sunken); }
.danger-zone { border-color: var(--color-danger-border); }

Accessibility

Role and pattern

A card is structure, not a widget: a <section aria-labelledby> (or <article> for a self-contained item) whose heading is the .card__title. There is no APG widget for it; follow the APG landmark regions guidance. An interactive card is one <a>; never nest a second link or button inside it.

Keyboard

KeyAction
TabMoves through the links and buttons inside the card; a static card is not a stop.
EnterFollows an interactive card's link.
Screen-reader heading keysJump between cards by their titles, so every card needs a real heading.

Focus

The shared ring (2px --color-focus-ring, 2px offset) is drawn on the interactive card itself. Focus never lands on a static card.

Labelling

The card's accessible name is its title (aria-labelledby → the heading id). A list card that has no visible title takes aria-label ("Notifications").

Motion

Only the interactive card moves: shadow, edge and a 1px lift over --duration-fast. Reduced motion zeroes the duration and removes the lift.

Touch

An interactive card is one large target. Actions in a card footer are 44px buttons with --space-3 between them.

Content

  • Titles are short nouns in sentence case: "Details", "Progress", "Sign-in and security", "Delete account".
  • One topic per card. If a card needs two headings, it is two cards.
  • Lead with the fact, not the label: the description list in Details starts with what the member asked for.
  • Danger-zone copy says what is lost before the button: "Removes your profile, saved list and messages."
