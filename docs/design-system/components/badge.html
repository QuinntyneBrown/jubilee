Badge

Badges are small, quiet labels for status and counts: a product that is sold out, a request awaiting reply, two unread messages. The Verified mark is a sibling that sits beside every verified business.

Overview

Use a badge for a one- or two-word status of a record, or a count on a navigation item. Badges are not buttons; to filter by a status use a Chip. For a message about the page, use an Alert and banner.

  • Tones: neutral (.badge) for finished or inactive states ("Completed", "Cancelled"); info for "Ready to review"; success for "Listed", "Confirmed" and, on a listing page and a business card, "Replies fast" (L2-054); warning for "Sold out", "Awaiting reply"; danger for "Declined".
  • Solid (.badge--solid): gold with ink text for a rare highlight ("New"). At most one per card.
  • Count (.badge--count): a gold pill with tabular figures on tabs, the tab bar and icon buttons; carries an aria-label such as "2 unread".
  • Verified (.verified): not a pill but a success check icon and the word "Verified" in muted text, beside a business name.

Anatomy

  1. DotAn 8px (--indicator-size) circle in currentColor, so status never rests on background colour alone. Hidden on count badges.
  2. Label--text-overline: uppercase, wide tracking, one or two words.
  3. ContainerPill, --badge-height (20px) tall, --space-2 inline padding, tone background.

Sizes

One size: 20px (--badge-height), with an 8px dot. Counts are at least 20px wide so single digits stay round. Verified follows the surrounding text size with a 16px icon.

States

Counts update in place; announce changes through the page’s live region ("New message from Legacy Financial"), not by making the badge live.

Responsive behaviour

  • Badges never wrap (white-space: nowrap). In a narrow row the meta line wraps around the badge instead.
  • In the phone tab bar the count badge sits on the icon’s corner; on desktop the same count sits after the label.
  • Keep labels to two words so a badge fits beside a 360px row title.

Theming

Each tone reads its status pair: --color-{info,success,warning,danger}-bg and -fg. Solid and count read --color-accent and --color-fg-on-accent. Dark mode swaps every pair and keeps them at 4.5:1.

.badge--success { background: var(--color-success-bg); color: var(--color-success-fg); }
.badge--count { background: var(--color-accent); color: var(--color-fg-on-accent); }

Accessibility

Role and pattern

Plain inline text in a <span>; no role. The word is the meaning. A count badge carries aria-label with the noun ("2 unread") because a bare number means nothing out of context. There is no APG pattern for static labels; status changes use a live region (APG landmark regions and role="status").

Keyboard

KeyAction
NoneBadges are not focusable. The tab or button they sit on handles the keyboard.

Focus

None of its own. When a badge sits in a focusable tab or button, that control’s focus ring surrounds both.

Labelling

Status badges read as their text. Count badges set aria-label="N unread"; on icon-only buttons put the count in the button label ("Notifications, 3 unread") and hide the dot. The Verified icon is aria-hidden; the word "Verified" (visible or visually hidden) is what is read.

Motion

None. Counts change without animation.

Touch

Not a target. Never make a badge clickable; use a chip or a link.

Content

  • One or two words, a state not an instruction: "Sold out", "Awaiting reply", "Listed". Written in sentence case; CSS uppercases it.
  • Pick the tone from what the person should feel: success when done well, warning when someone needs to act, danger when something stopped. Neutral when it is simply over.
  • Counts above 99 show "99+" with the full number in the aria-label.
  • "Verified" is the only word for a business the verification team has approved. Do not use "Trusted" or "Approved".
