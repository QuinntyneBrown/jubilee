Text field

A text field takes one line of typed input: a name, an e-mail, a price, a day. It is always inside a form field with a visible label, except the search box, whose label is hidden but present.

WCAG 2.2 AAStatus: stableNative <input>.input on every form mock

Overview

Use a text field for short, free-form values. Use a Textarea for more than a sentence, a Select for a fixed list, and radios for two to five visible options. The label, help, error and counter belong to the Form field around it.

  • Text, e-mail, URL, number: one .input with the right type, autocomplete and inputmode.
  • Password: .password-input puts a show-password button inside the right edge of the control, so a visitor can check what they typed (Log in and Sign up, L2-187).
  • Search: .search wraps the input with a leading icon inside a role="search" form.
  • Date: the native date picker (book a meeting, request a quote); Jubilee does not ship a custom calendar.
  • Prefix add-on: .input-group .addon for a fixed unit such as $ on prices.
  • Read-only with action: the share dialog's link field with a Copy button.

Anatomy

  1. Label.field__label with a required/optional marker; see Form field.
  2. Help.field__help before the input, linked by aria-describedby.
  3. Input.input: 44px, --radius-md, hairline --color-border-strong edge (3:1), surface fill, body text.
  4. Counter.field__counter, right-aligned caption, also in aria-describedby.

Sizes

Medium (44px) is the default everywhere. Small (32px) is for inline toolbars such as Sort; large (48px) for the hero search on phones. Log in and Sign up keep the medium control at every width; the design draws theirs at 48px under 1024px with a 12px radius, a known difference (ADR 0038).

Password

The button is static in these docs. It is named for what it will do: “Show password” while the control is type="password", “Hide password” while it is type="text". On hover its icon goes from --color-fg-muted to --color-fg-default; the kit has no data-state hook for that, so it is not in the matrix. A failed submit clears the password, so the control comes back hidden.

Both themes

  • Invalid thickens the border to 2px in --color-danger-solid (border plus inset shadow), so the change is not colour alone, and the field shows its error text.
  • Read-only is used while a form submits (edit-listing submitting): values stay readable and selectable but cannot change. A read-only password keeps its button, on the sunken fill.
  • Disabled is rare: a field that does not apply is hidden or explained, not greyed out.

Responsive behaviour

  • Inputs are fluid (width: 100%) and take their width from the form grid; two-column rows collapse to one under 640px.
  • Font size never drops below 16px on phones so iOS does not zoom on focus (the small size is desktop-only).
  • The top-bar search shows from 1024px; below that the search icon links to the search page, and the phone hero shows a large search instead.
  • Add-ons keep their width; the input shrinks. Long read-only values scroll inside the input, never overflow.

Theming

Each field reads four component tokens set from semantic ones: --field-bg, --field-fg, --field-border, --field-border-hover. On the brand band the top-bar search re-maps them to on-brand tokens and takes the pill radius.

.topbar--ink .search .input { background: var(--color-bg-on-brand-subtle); border-color: var(--color-border-on-brand); color: var(--color-fg-on-brand); }

In dark, inputs sit on the dark surface with a lighter strong border; placeholder text uses --color-fg-subtle, which holds 4.5:1 in both themes.

Accessibility

Role and pattern

Native <input> with the correct type. Search sits in a <form role="search">. The show-password button is a plain button (APG button pattern) that is renamed rather than pressed: “Show password”, then “Hide password”. It carries no aria-pressed, so a screen reader says what the sighted label would say (ADR 0038). It is type="button" and changes only the type of the control. Native date inputs keep the browser's accessible picker.

Focus

A 2px --color-focus-ring outline at zero offset plus a matching border, so the ring hugs the field's --radius-md corners.

Labelling

Every field has a visible <label for>; the search label is visually hidden. Help, error and counter ids go in aria-describedby. Placeholders are examples, never labels. The show-password button has an aria-label that changes with its state, and its icon is hidden. Shown or hidden, the password stays one input with its autocomplete value, so a password manager fills it as before. Use autocomplete tokens (email, current-password, new-password, given-name, street-address) for 1.3.5.

Motion

Border colour and shadow transition over --duration-fast; reduced motion zeroes it.

Touch

Medium and large fields are 44px and 48px tall and full width. The show-password button is 44px wide and as tall as the control. Small fields are pointer-only.

Content

  • Labels are short nouns in sentence case: “E-mail”, “Business name”, “Price”. No colon.
  • Mark required and optional fields in words: “(required)”, “(optional)”. Sign up marks only its optional field; see Form field.
  • Log in and Sign up label the address “Email”, with the placeholder “you@example.com”, as the design does. Every other screen still says “E-mail” until the vocabulary changes across the product (ADR 0038).
  • The show-password button is named “Show password” and “Hide password”: the verb says what pressing will do.
  • Help text says what makes a good answer or a limit: “At least 10 characters.”
  • Placeholders, where used, are examples (“Plumber, lawyer, Bibles…”), never instructions.
  • Use Canadian formats: “$34.00”, dates as “Thu 12 Nov 2026” in text.
