Form field

A form field is the frame around one control: what it is, whether it is needed, how to answer, and what went wrong. Every input, select and textarea in Jubilee sits in one.

WCAG 2.2 AAStatus: stable.fieldOn every form mock

Overview

Wrap every Text field, Textarea and Select in .field. Groups of checkboxes and radios use a fieldset with the same help and error parts. The order is label, help, control, error, counter; Sign up, as designed, moves the help under the control.

  • Label always visible; the marker says “(required)” or “(optional)”. Sign up marks only its optional field.
  • Label action (optional): a link on the line of the label, at its right end, for help with this field only (“Forgot password?” beside “Password”).
  • Help before the control, so it is read before typing. On Sign up the hint sits under the control; an error then sits between the control and the hint.
  • Error after the control, replacing nothing: help stays.
  • Counter last, right-aligned.

Anatomy

  1. Label.field__label, --text-label, linked with for.
  2. Marker.optional: “(required)” or “(optional)” in --color-fg-subtle, regular weight.
  3. Help.field__help, --text-body-sm, muted.
  4. ControlInput, select or textarea with aria-describedby listing help and error ids.
  5. Error.field__error in --color-danger-fg with a warning glyph; the control gets aria-invalid="true".

Sizes

The field has no sizes of its own; its control takes the text-field and select sizes and the field's width comes from the form layout.

States

The field reflects its control. Hover and focus change only the control; invalid adds the error line; disabled greys label text only through the control. Active shows focus.

Responsive behaviour

  • Fields stack label-over-control at every width; Jubilee never puts labels beside fields in forms (the inline sort is a toolbar, not a form).
  • Help and error text wrap; they never truncate.
  • In two-column grids, help text of unequal length is fine; controls align because help sits above them in both.
  • Where the hint sits under the control (Sign up), the controls of a pair align because nothing stands between a label and its control.
  • A label action stays on the line of the label at every width; keep both short enough to share 240px.

Theming

Label --color-fg-default, marker --color-fg-subtle, help --color-fg-muted, error --color-danger-fg. All four hold their contrast on canvas, surface and raised surface in both themes. A label action is a Link and takes --color-fg-link.

Accessibility

Role and pattern

Plain markup: <label for>, the control and aria-describedby. No ARIA pattern beyond the APG names and descriptions practice; groups use fieldset/legend.

Keyboard

KeyAction
TabMoves to the control; label, help and error are not focus stops.
Tab with a label actionReaches the action first, then the control: “Forgot password?”, then “Password”.
Click or tap the labelFocuses the control (or toggles a checkbox).

Focus

On the control (2px --color-focus-ring). On submit with errors, focus goes to the form's error summary, whose links move focus to each field.

Labelling

The label text plus marker is the accessible name; help and error are the description, in that order. required is set on the control as well as the visible marker; on Sign up the control carries required alone, so assistive technology still announces it. Where the hint sits under the control, aria-describedby still lists help, then error. Errors are not announced as they appear on blur; they are collected in the summary on submit.

Motion

None. Errors appear without animation so their position never shifts while being read.

Touch

The label is a target too, which enlarges every control's hit area.

Content

  • Labels: nouns in sentence case, no colon.
  • Mark both: “(required)” and “(optional)”; members fill long forms faster when nothing is implied.
  • The exception is Sign up, which marks only “Home church (optional)” and “Home church address (optional)”: its four other controls carry required and no “(required)” text (L2-126, ADR 0038). Log in marks nothing.
  • A label action is two or three words that help with this field: “Forgot password?”.
  • Help: what a good answer looks like or a limit. Plain, one sentence.
  • Errors say what to do, with the numbers: “Use at least 10 characters. This one has 5.” Never “Invalid input.”
