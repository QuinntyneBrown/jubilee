Timeline

The timeline answers "where is this at?" for one request or listing: Joanna asked WaterWorks on Monday, WaterWorks usually replies within a day, then she accepts and arranges a visit. Each step is done, current, next, or stopped.

Overview

Use a timeline for the steps of one record’s process, shown read-only beside its details: a quote or booking request, a listing going through verification. Use a Stepper for steps the person moves through in a form, and a Notification item list for an activity feed across many records.

  • In progress: done steps (data-complete, green check), one current step (aria-current="step", gold), then upcoming steps (outlined).
  • Stopped: the step where the process ended carries data-stopped (red ×), and no steps follow it. Used for declined and cancelled requests.
  • Finished: every step done; the last one says what happened ("Completed").

Anatomy

  1. DotA 24px (--target-min) circle with a 2px edge. Done is success solid with ✓, current is gold, stopped is danger solid with ×, upcoming is outlined. The glyph is aria-hidden.
  2. ConnectorA 2px --color-border-default line from each dot to the next; none after the last step.
  3. Title.timeline__title: who did what, --text-label. Starts with visually hidden status text ("Done:").
  4. Meta.timeline__meta: when it happened or when to expect it, muted --text-body-sm. Omit it rather than leave it empty.

Sizes

One size. The dot is 24px so the ✓ and × glyphs stay legible; steps are spaced --space-5. In a narrow card the text wraps beside the dot.

States

Timeline steps are not interactive, so they have no hover, focus, active or disabled state. Each step has one of four status states, set with real attributes.

Responsive behaviour

  • The timeline is a single column at every width. On request detail it sits in the right column of .split from 1024px and below the details on phones.
  • Titles and meta wrap beside the dot; the connector stretches with them.

Theming

Dots read status solids (--color-success-solid, --color-danger-solid, --color-accent) with their on-colours, the upcoming dot reads --color-border-strong on --color-bg-surface, and the connector reads --color-border-default. Dark mode swaps them; the current gold keeps its darker --color-accent-border edge.

Accessibility

Role and pattern

An ordered list (<ol>): readers announce "list, 3 items" and each position. The current step carries aria-current="step". Each title starts with visually hidden status text ("Done:", "Current step:", "Next:", "Stopped:") because the dot is decorative. There is no APG widget for read-only progress; this follows the APG structural roles guidance for lists.

Keyboard

KeyAction
NoneNot focusable. Actions about the request (Message, Cancel request) sit outside the timeline.

Focus

None.

Labelling

Put the timeline under a heading ("Progress"). Titles name the actor: "WaterWorks declined", "You asked". Status is in text, not only in dot colour or glyph.

Content

  • Titles say who does what, in the past tense when done ("Legacy Financial confirmed") and as an expectation when upcoming ("WaterWorks replies with a quote").
  • Meta gives the time when done ("Today, 9:14 a.m.") and the expectation when upcoming ("Usually within a day", "Within two business days").
  • Three to five steps. A stopped timeline ends at the stop; do not show the steps that will now never happen.

Drift fixed during extraction: the dots were correctly aria-hidden, but no step had status text, so a screen reader heard the titles with no idea which were done or stopped (only aria-current was announced); the docs add visually hidden "Done:" / "Current step:" / "Next:" / "Stopped:" prefixes. Upcoming steps carried empty .timeline__meta divs; omit them. The listing-review timeline had an inline style="text-align: left; margin-top: …" to undo its centred parent. The connector offset is computed from --target-min and the hairline, so changing the dot size moves it correctly.
