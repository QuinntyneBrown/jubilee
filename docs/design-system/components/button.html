Button

Buttons let a member or business take an action: book, request, send, save, delete. Jubilee buttons are pills; the gold primary marks the one action a view exists for.

Overview

Use a button when activating it changes something: it submits a form, sends a request, opens a dialog or deletes. Use a Link when it only takes the person somewhere; an <a class="btn"> is allowed for navigation that should look like an action ("List your business", "Book a meeting" that opens a dialog page). Use a Menu when one trigger offers several actions.

  • Primary (gold, ink label) is the one action the view exists for: Book a meeting, Send request, Publish listing. Never two per view.
  • Secondary (the default look: white pill, strong border) is for every other action: Message, Cancel, Save draft.
  • Ghost sits in dense or branded surfaces: top-bar icons, row actions, card corners (the save heart).
  • Link looks like a link but is a button; use it for low-emphasis actions such as View all or Retry inside a sentence.
  • Danger is for destructive actions (Delete listing, Delete account) and only appears inside a confirmation dialog or a danger zone.

Anatomy

  1. Leading icon (optional)1.25em square from the icon set, inherits the label colour, aria-hidden.
  2. LabelA verb phrase in sentence case; it is the accessible name.
  3. ContainerPill (--radius-full), height from --control-height-*, 1px border, padding --space-3/4/6. Primary carries a darker gold edge (--color-accent-border) because gold on cream is only 1.6:1.

Variants

Variants change emphasis, not meaning. Pick by how much attention the action deserves on this view.

Emphasis from highest to lowest; danger is reserved for destructive confirmations.

The mark is Google's and is used unaltered, in its four colours, on the neutral button, as Google's sign-in branding guidelines ask (ADR 0038). Its four fills are attributes of the SVG; they are the only colour values in the system that are not tokens. While the form submits the button is disabled; when Google sign-in is not configured it is not rendered, and neither is the Divider under it (L2-003).

Known difference: the design sets this button in Roboto with Google's grey edge. The product keeps the default button, with the system text face and --color-border-strong, at --control-height-lg.

Sizes

Medium is the default. Small lives in top bars, rows, cards and toolbars; large is for detail-page actions, hero and auth screens where the button is the point.

Heights --control-height-sm/md/lg (32/44/48px); padding --space-3/4/6; label --font-size-sm/md/lg.
HTML
<button class="btn btn--primary btn--sm" type="button">Small · 32px</button>
<button class="btn btn--primary" type="button">Medium · 44px</button>
<button class="btn btn--primary btn--lg" type="button">Large · 48px</button>

Both themes

  • Loading keeps the width, hides the label behind a spinner, sets aria-busy="true" and ignores clicks. Dialog footers use it on the confirm button while the request is in flight (busy mocks).
  • Disabled uses the native attribute and 50% opacity. Jubilee prefers an enabled button that explains the problem on press; a disabled submit with no reason is drift.
  • Pressed toggle buttons use aria-pressed; see Button group.

Responsive behaviour

  • Below 640px (--layout-breakpoint-sm) the primary action on a detail page takes the full row (.detail-head__actions .btn--primary), with icon buttons beside it on the next row.
  • Dialog footers keep buttons on one row and wrap when they do not fit; the primary stays last (rightmost, or bottom when wrapped). On phones the dialog becomes a sheet and its footer stays sticky.
  • The top bar swaps text buttons for icon-only ghost buttons below 768px (.only-desktop / .only-narrow).
  • Labels never truncate. A label that wraps at 360px is too long; shorten the verb phrase.

Theming

The button reads semantic tokens through five component tokens (--btn-bg, --btn-fg, --btn-border, --btn-bg-hover, --btn-bg-active) that each variant and each brand surface overrides. A theme changes semantic tokens; a re-skin overrides component tokens; neither edits .btn.

/* How the hero band re-maps the ghost button */
.hero .btn--ghost { --btn-fg: var(--color-fg-on-brand); --btn-border: var(--color-border-on-brand); --btn-bg-hover: var(--color-bg-on-brand-subtle); }

Gold stays gold in the dark theme, and its label stays ink (--color-fg-on-accent) in both, at 11.15:1. The danger button flips: red-300 fill with a red-950 label in dark.

Accessibility

Role and pattern

Native <button type="button"> (or type="submit" in a form). A navigation that looks like a button is an <a class="btn" href>; never a <div> with a click handler. See the APG button pattern.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order.
Enter, SpaceActivates. Space fires on key up, so a mis-press can be cancelled by moving away. Links styled as buttons respond to Enter only.
EscNo effect on the button; a loading action cannot be cancelled with Esc, so long actions get a separate Cancel.

Focus

The shared ring (2px --color-focus-ring, 2px offset) appears on :focus-visible only. It is ink in light and gold in dark; on the brand band it switches to --color-focus-ring-on-brand so it stays above 3:1 against ink.

Labelling

The visible label is the accessible name. Icon-only buttons set aria-label naming the action and its object ("Save Luzandre.com", "Delete Faith heavyweight tee, charcoal"). Count dots on icon buttons go into the label ("Notifications, 3 unread"), never only into the dot. The Google mark is aria-hidden: the label already names Google.

Motion

Background, border and shadow transition over --duration-fast (120ms); active nudges 1px down. Reduced motion zeroes the transition through the tokens and removes the nudge. The loading spinner keeps turning: it is status, not decoration.

Touch

Medium (44px) and large (48px) meet the 44px comfortable target. Small (32px) only appears where neighbours are 8px or more apart, which keeps the 24px target-spacing rule (2.5.8).

Content

  • Labels are verb phrases in sentence case: "Book a meeting", "Request a quote", "Send request", "Publish listing". Never "OK", "Yes", "Submit" or "Click here".
  • Name the object when the context does not: "Delete listing" in the dialog, "Delete" in a row whose name is already in the aria-label.
  • Destructive labels name the loss: "Delete account", not "Confirm". Their partner is "Keep my account" or "Cancel".
  • Keep to three words where possible. Loading never changes the label; progress text goes in a live region.
  • The Google button says “Continue with Google” on Log in and “Sign up with Google” on Sign up, exactly.
