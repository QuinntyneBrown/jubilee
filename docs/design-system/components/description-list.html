Description list

A description list shows the facts of one thing as label–value pairs: where Legacy Financial meets, what Joanna asked WaterWorks for, how the Faith tee fits. It is read, not edited.

WCAG 2.2 AAStatus: stableNative <dl>61 uses in the mocks

Overview

Use a description list for the read-only fields of a single record, three to eight pairs long. Use a Table to compare several records, a List for a run of records, and form fields when the values are editable.

  • Plain (.dl) on a card or page: muted labels in a max-content column, values beside them.
  • In a well (.dl.well) on a sunken background, used in admin dialogs to set the record apart from the decision around it.

Anatomy

  1. Term<dt>: --text-label in --color-fg-muted. A noun or short phrase, no colon.
  2. Description<dd>: body text in --color-fg-default; may hold a link, badge or several values joined by " · ".
  3. Gridmax-content 1fr columns with --space-2 row and --space-6 column gaps; one column under 640px.

Sizes

One size. Labels use --text-label and values --text-body. Inside dense surfaces (dialogs, cards), wrap it in a .well rather than shrinking the type.

States

A description list is static content: it has no hover, focus, active or disabled state. Links and buttons inside a value keep their own states. What varies is the data.

Responsive behaviour

  • From 640px up: two columns, labels sized to the longest label (max-content).
  • Below 640px: one column, the label above its value, --space-3 after each value. The rule lives with .row--stack in components.css but applies to every .dl.
  • Long values (addresses, e-mails) wrap; nothing truncates.

Theming

Only semantic tokens: --color-fg-muted for terms, inherited --color-fg-default for values, and --color-bg-surface-sunken when wrapped in .well. Dark mode swaps them.

Accessibility

Role and pattern

Native <dl> with <dt>/<dd> pairs as direct children. Screen readers announce it as a description list with term and definition pairs. There is no APG widget pattern; it is plain structure (see APG structural roles).

Keyboard

KeyAction
TabOnly reaches links or buttons inside values; the list itself is not focusable.

Focus

No focus of its own. Links inside values use the shared ring.

Labelling

Give the list a heading above it ("Details", "About"). Each term labels the value that follows; do not repeat the term inside the value. Use "Not given" rather than an empty or dash value.

Motion

None.

Touch

Not interactive. Links inside values are inline text links; keep them on their own value so the target is the full line.

Content

  • Terms are short nouns in sentence case: "Where", "Hours", "Ready in", "Member since". No trailing colon; the layout already pairs them.
  • Values use the same formats as the rest of Jubilee: "Mon–Fri 9:00–5:00", "5–7 days", "East York, M4C".
  • Three to eight pairs. More than that belongs in sections with their own headings.
