Accordion

An accordion lets a member scan a list of questions and open only the answer they need. Jubilee builds it from native <details>, so it works without script and the browser handles the keyboard.

WCAG 2.2 AAStatus: stableNative <details>Help page only

Overview

Use an accordion for reference content people scan by question: the Help page FAQ is the only use in the mocks. Do not hide information a person needs to finish a task (prices, requirements, the reason a request was declined) inside one; show it. For switching between peer views use Tabs; for a single show-more toggle a lone <details> without the frame is enough.

  • Independent (default): each item opens on its own; several can be open.
  • Exclusive: add the same name to every <details> and the browser closes the others when one opens. Use it only when answers are long and comparing them is unlikely.
  • First item open: the Help page opens the most-asked question so the page never looks empty.

Anatomy

  1. Summary<summary>: the question, --text-label, padding --space-4, at least 44px tall.
  2. IndicatorA + drawn in CSS, --color-fg-subtle; it turns 45° to read as × when open.
  3. Panel.accordion__body: muted body text, padding --space-4 at the sides and bottom.
  4. Frame.accordion: one surface with a hairline edge, --radius-md, and hairline rules between items.

Responsive behaviour

  • The accordion fills its column. On the Help page it takes the wide side of .split from 1024px and the full width below.
  • Questions wrap; the indicator stays top-right and never shrinks (gap: --space-4).
  • Nothing changes at 360px except line length. Do not convert tabs into an accordion on phones without checking that people need only one section at a time.

Theming

The frame uses --color-bg-surface and --color-border-default; hover fills the summary with --color-bg-subtle. Dark mode swaps those semantic tokens only; the indicator stays --color-fg-subtle, which keeps 3:1 on the dark surface.

Accessibility

Role and pattern

Native <details>/<summary>: the summary is exposed as a button with an expanded state, no ARIA needed. This is the APG disclosure pattern repeated; the APG accordion pattern also asks that each header sit in a heading, so on long pages wrap the summary text in an <h3>.

Keyboard

KeyAction
Tab / Shift+TabMoves between summaries, then into links inside open panels.
Enter, SpaceOpens or closes the focused item.
Find in pageBrowsers open a closed <details> when find-in-page matches its content.

Focus

The shared ring is drawn round the summary (2px --color-focus-ring, 2px offset). Focus stays on the summary when the panel opens.

Labelling

The summary text is the button's name. Keep the question in the summary and nothing else: no extra links or buttons inside it.

Motion

The indicator rotates over --duration-base; the panel opens instantly. Reduced motion zeroes the rotation through the token.

Touch

Each summary is the full width of the frame and at least 44px tall (--target-comfortable).

Content

  • Write summaries as the question a member would ask, in their words: "Does Jubilee take payment?"
  • Answer in the first sentence ("No.", "Yes."), then explain. Two or three sentences per answer.
  • Order by how often people ask, not alphabetically.
  • Keep to about eight items; past that, group them under headings.
