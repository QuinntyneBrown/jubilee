Notification item

A notification item tells a member one thing that happened and takes them to it in one tap: "Legacy Financial confirmed your meeting". Unread items are tinted gold until opened or marked read.

Overview

Use notification items only on the Notifications page, in a .list.card.card--list. They are the record of events. For a message that interrupts the current task use a Toast; for a page-level condition (offline, verify your e-mail) use an alert or banner. A notification about a message links to the conversation; the conversation itself is a Message thread.

  • Unread (.notif--unread): gold-subtle fill, bold title, hidden "Unread.".
  • Read (.notif): transparent, regular title.
  • Each item: a round icon for the kind of event (calendar, message, bag, store, check), a title sentence, one line of detail and a time.

The page header carries Mark all as read (secondary Button) and a ghost Settings link to notification preferences. See the Notifications pattern for which events notify and how.

Anatomy

  1. Icon.notif__icon: 40px (--avatar-size-md) circle on --color-bg-subtle, event icon, aria-hidden.
  2. Title.notif__title, --text-label; bold when unread. Starts with a hidden "Unread." when unread.
  3. Detail.notif__meta, --text-body-sm muted: the when/what of the event, or the quoted message.
  4. Time.text-caption: when the event happened.
  5. ContainerThe whole item is a link; unread fills with --color-accent-subtle; hairline divider below.

Two variants: unread and read. The icon names the event type.

  • Unread hover shows no change today: .notif--unread is declared after the hover rule and wins. A --color-accent-subtle-hover fill is proposed for it.
  • Active has no look of its own; the tap navigates.
  • Loading: five skeleton items (circle + two bars), list aria-hidden, a hidden role="status" "Loading notifications…". Mark all as read is hidden until loaded.
  • Empty: an Empty state ("No notifications yet") that says what will appear here and offers Browse businesses. All read (pages/notifications/read) keeps the list with every item read and the subtitle "You’re all caught up".
  • Mark all as read clears the fills at once, updates the subtitle and the top-bar dot, and announces "3 notifications marked as read" in the toast region.

Responsive behaviour

  • The list is full width in the narrow container at every size; items never become cards in a grid.
  • Titles and details wrap; nothing truncates, because the sentence is the content.
  • Below 640px the page header actions wrap under the title; Mark all as read stays a text button.

Theming

Unread uses --color-accent-subtle, the same fill as a current thread, so "new to you" looks the same in Notifications and Messages. In dark mode the gold-subtle is a deep olive and text stays above 4.5:1. The icon circle uses --color-bg-subtle in both themes.

Accessibility

Role and pattern

A <ul> of native links (APG link pattern). Mark all as read is a button; its result is announced through the polite toast region.

Keyboard

KeyAction
Tab / Shift+TabHeader actions first (Mark all as read, Settings), then item to item.
EnterOpens the item's target and marks it read.
Enter, Space on Mark all as readMarks every item read; focus stays on the button.

Focus

The shared ring around the whole item. After Mark all as read, focus stays on the button so the person can carry on down the list.

Labelling

The link name is the hidden "Unread.", the title, the detail and the time, read in order. The icon is aria-hidden; the title carries the meaning. Times should be <time datetime> elements in product. The top-bar bell names the count ("Notifications, 3 unread").

Motion

None. Read fills clear instantly.

Touch

Items are full-width and at least 80px tall. Mark all as read and Settings are 44px buttons.

Content

  • Title: who did what, in the past tense, as a sentence without a full stop: "Legacy Financial confirmed your meeting". The business name first.
  • Detail: the one fact the person needs next: the slot ("Thu 12 Nov, 10:00 a.m. by video"), the item and pickup, or the message itself in curly quotes.
  • Time: "9:14 a.m." today, "Yesterday, 6:02 p.m.", "Sat 7 Nov" this week, "14 Oct" before that.
  • No "You have a new notification". If the title does not say what happened, rewrite it.
