Alert and banner

Alerts put a message inside the content it is about: a request's status, a failed save in a dialog, the form error summary. Banners stretch an alert across the top of the page for a condition that lasts: offline, e-mail not confirmed.

Overview

Use an alert when the message belongs to one place on the page and should stay there while it is true: "Waiting for WaterWorks to reply" on a request, "Sold out in every size" on a product, "We couldn’t delete it" in a dialog. Use a banner when the condition affects the whole app or account. Use a Toast for a passing outcome, and Inline message for one field.

  • Info (default, no modifier): neutral status, waiting, how something works.
  • Success: a saved or finished state that the person may want to act on ("Listing updated · View public listing").
  • Warning: something needs attention but nothing is broken ("You’re offline").
  • Danger: an action failed, or the form has errors. The .form-summary variant lists them as links to the fields.
  • Banner (.alert.banner): full-bleed, no radius, sits above <main>. Persistent banners have no dismiss button; they go away when the condition ends.

Anatomy

  1. Tone icon--icon-size-md in --alert-icon; aria-hidden, so the title must carry the meaning.
  2. Accent edge--border-width-accent on the start side in the tone border colour. Banners use a hairline bottom edge instead.
  3. Title.alert__title, --text-label. Required on inline alerts; banners use a leading <strong> sentence instead.
  4. TextOne or two sentences in --alert-fg.
  5. Actions (optional).alert__actions: links or small buttons, label font, inheriting the tone colour.
  6. Dismiss (optional).close, 24px, only for messages the person may safely hide.

Responsive behaviour

  • Inline alerts take the full width of their container and wrap; the icon stays top-aligned with the title.
  • Banners centre the message and actions on one line from 640px and wrap actions under the text below it (.banner .alert__body wraps).
  • On phones a banner sits under the top bar and scrolls with the page; it never becomes sticky, so it does not eat the small viewport.
  • Long addresses such as joanna.adeyemi@example.com break with overflow-wrap: anywhere rather than overflowing.

Theming

Each tone sets four component tokens, --alert-bg, --alert-fg, --alert-border and --alert-icon, from the matching --color-{tone}-* semantic tokens. Dark theme swaps those to deep tinted fills with light text, so the modifier classes never change.

.alert--warning { --alert-bg: var(--color-warning-bg); --alert-fg: var(--color-warning-fg);
  --alert-border: var(--color-warning-border); --alert-icon: var(--color-warning-icon); }

Accessibility

Role and pattern

Status messages use role="status" (polite); failures and the error summary use role="alert" (assertive). An alert that is in the page on load is not announced, which is correct: it is read in order. See the APG alert pattern; WCAG 4.1.3.

Keyboard

KeyAction
TabMoves to the alert's actions and dismiss button in DOM order.
Enter / SpaceActivates the focused action or dismiss.
Error summaryOn a failed submit, focus moves to the summary (tabindex="-1"); each link moves focus to its field.

Focus

The global ring (2px --color-focus-ring, 2px offset) on links, buttons and dismiss. After dismissing, focus moves to the next focusable element after where the alert was, never to the top of the page.

Labelling

The title is the message: an icon alone never carries tone. Dismiss buttons are labelled "Dismiss". Error summary links use the same words as the field error they point to.

Motion

Alerts and banners appear without animation; the page reflows once. Nothing loops.

Touch

Dismiss is 24px (--target-min) with 12px around it; banner action buttons are 32px small buttons spaced --space-4 apart.

Content

  • Titles state the situation: "Waiting for WaterWorks to reply", "You’re offline". Not "Notice" or "Error".
  • Failures say what did not change: "Nothing was sent and what you typed is still here."
  • Banners open with one bold sentence and follow with the consequence: "You’re offline. Showing the directory saved at 8:42 a.m."
  • Error summary title counts: "Fix 2 things to continue". Each item says how to fix it, not what is wrong.
