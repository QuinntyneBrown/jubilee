Event place

Where an event is, in one or two lines: a map-pin and “{venue}, {area}” for an event in Toronto, a broadcast icon and “Streamed live” for a stream, and “Also streamed live” under the venue when it is both.

WCAG 2.2 AAStatus: newevent-placeL2-302 AC4

Overview

  • The venue and the area only. The street address and the stream link are for members going, and the event page shows them beside this block, never in it (L2-302 AC4, L2-312 AC3).
  • Compact in a row of the list; default in the feature card; full on the event page, where the venue is never cut.

Anatomy

  1. IconMap pin or broadcast, 16 px, --color-success-icon, decorative.
  2. Venue text.event-place__text: “{venue}, {area}”, cut with an ellipsis except in --full.
  3. Second line“Also streamed live” when the event is held in Toronto and streamed.

Sizes

Two sizes by modifier: the default (body-small, in the feature card’s facts) and --compact (caption, muted, in a row). --full changes truncation, not size.

States

None: it is static text.

Responsive behaviour

The lines sit side by side when they fit (--space-4 apart) and wrap under each other when they do not. In a row the venue is cut with an ellipsis at the width of the column, so a long venue never pushes the RSVP button; the full text stays in the accessibility tree.

Theming

The icons use --color-success-icon (green) in both themes; the text inherits, or is muted in --compact.

Accessibility

Both icons are aria-hidden: the text says the format (“Streamed live”, “Also streamed live”). Truncation is visual only, so a screen reader reads the whole venue (L2-302 AC4).

Content

  • “{venue}, {area}”: “Sam James Coffee Bar, Harbord Village”. Never the street number and street.
  • “Streamed live” for a stream alone; “Also streamed live” as the second line of an event that is both.
