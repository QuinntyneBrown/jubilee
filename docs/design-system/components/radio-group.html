Radio group

A radio group asks for exactly one answer from a short, visible list: how to get an order, what's wrong with a listing, whether a business offers products or services.

WCAG 2.2 AAStatus: stableNative type="radio"Choice cards: 57 uses

Overview

Use radios when there are two to five mutually exclusive options and members should see them all before choosing. Use a Select for longer lists, a Checkbox when several can be on, and a Button group only for view switches that are not form data.

  • Radio list: .choice rows in a fieldset, optionally with a description line (order request: Ship to me / Pick up).
  • Choice cards: .choice-cards with .choice-card tiles, icon, title and text, for a decision that shapes the rest of the form (list your business: Products / Services). Two columns from 640px.
  • Chip radios: time slots and sizes (book a meeting, product) are radios styled as chips; see drift.

Anatomy

  1. LegendNames the question; marked required.
  2. Icon.choice-card__icon: 40px circle, gold when selected.
  3. Title.choice-card__title, label weight.
  4. Text.choice-card__text, muted small text.
  5. HelpGuidance for the whole group under the cards.

Sizes

Radios have one size (20px circle, 24px row). Choice cards fill their grid cell; minimum height comes from the content, and both cards in a row match heights.

States

Forced with data-state (on the input for radios, on the label for cards). Each cell is its own group so selected and unselected can be shown. Active keeps the hover look.

Responsive behaviour

  • Choice cards stack under 640px and sit two-up from 640px (.choice-cards).
  • Radio lists stay one per line at every width.
  • Chip radios wrap in a cluster with --space-2 gaps.

Theming

Selected radios fill --color-accent with an ink dot (--indicator-size). A selected choice card gets an ink (--color-fg-default) 2px edge and a gold icon; in dark the edge turns light, so it stays the strongest edge on the page.

Accessibility

Role and pattern

Native radios sharing a name, in a <fieldset> whose <legend> names the group. Follows the APG radio group pattern for free.

Keyboard

KeyAction
TabMoves into the group, landing on the selected radio (or the first), then out of the group.
↓ / →, ↑ / ←Move to and select the next / previous radio, wrapping.
SpaceSelects the focused radio if none is selected.

Focus

Radio: the shared ring around the circle. Choice card: the ring goes on the card (:has(input:focus-visible)) with a 2px offset.

Labelling

Each radio is wrapped by its label; a card's title and text are both inside the label, so the text is part of the name. Group errors use aria-describedby on each radio and aria-invalid.

Motion

Fill and edge transition over --duration-fast, zeroed under reduced motion.

Touch

Radio rows are at least 24px; choice cards are at least 72px tall and full width on phones.

Content

  • Legends ask the question (“How would you like to get it?”).
  • Options are parallel and short; put the cost or consequence in the description.
  • Order options by likelihood or naturally (sizes S → 2XL, times early → late).
  • Select a default only when it is safe; never default a report reason.

Sources

Extracted from these mocks:

  • pages/list-business/default (choice cards)

  • dialogs/order-request/default (radios with descriptions)
  • dialogs/report-listing/default (report reason)

Drift fixed during extraction: time slots and sizes are label.chip elements wrapping a visually hidden radio, each with style="position: relative" (55 times), and the chip CSS has no rule for a checked radio inside it, so the selected slot looks unselected and keyboard focus is invisible. The system documents them as radios and proposes .chip:has(input:checked) and .chip:has(input:focus-visible) rules. The report-listing legend marker used class="optional text-muted"; .optional alone is enough.
