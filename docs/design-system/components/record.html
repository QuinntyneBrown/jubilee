Record

Overview

The screen of one record of any table (L2-280 – L2-283): the way back to its table, its title, status and ID, its actions, its fields, what points to it and its history. The same screen views, edits and creates; deleting asks first (the delete dialog). It is schema-driven: each field is drawn as its type reads best, with the cell--* classes of the Records table.

Variants

Editing and creating

Edit turns the fields into labelled controls (record-fields--editing) and the actions into Cancel and "Save changes"; creating a record starts there with "New {thing}" as the title and "Create {thing}". Control widths follow the field: __short (12.5rem) for numbers, __mid (20rem) for choices, __ref (24rem) for a reference.

Read-only

A record of a read-only table (Audit records, Statement agreements, Consent records) has the lock tag --lg in place of its actions, and a note: "Jubilee writes these records itself. They can be read and exported, never changed." (.record-note).

Loading and error

Loading keeps the crumbs and draws skeletons for the title and the field rows, with a visually hidden "Loading {thing}…" heading and aria-busy="true". When the record cannot be read, an Empty state (empty--error, role="alert") says "We couldn’t load {thing} {ID}" with JB-ADM-504 and "Try again".

Responsive behaviour

  • Below 1024px the aside follows the fields; from 1024px it stands beside them, 18.75rem wide.
  • Below 640px each field's label sits above its value; from 640px they share a row.
  • The title wraps anywhere (IDs have no spaces); the actions wrap below it when they do not fit.

Theming

Fields sit on --color-bg-surface inside a --color-border-default card; labels and system values are --color-fg-muted. Edit is the inverse ink and Delete the danger outline in both themes.

Accessibility

Role and pattern

The crumbs are a nav named "Breadcrumb" with the record as aria-current="page". The fields are a description list (dl) in a section named "Fields"; editing labels every control with its dt. The aside is a complementary landmark named "Related and history", each part under its heading.

Keyboard

KeyAction
TabBack, Copy ID, Delete, Edit, each reference in the fields, then Points here and History links.
Enter on Copy IDCopies the ID and says "Copied" in the page's status region.
Esc while editingSame as Cancel; unsaved changes ask first (leave-unsaved).

Labelling

  • Copy ID is named "Copy ID {id}".
  • "Saved" is a role="status", so it is announced.
  • A field with no value shows a dash named "None".
  • Statuses are words; the pill's tone repeats them.

Motion

None of its own. The saving spinner stops under prefers-reduced-motion.

Content

  • The back link names the table ("Listing reports"); the last crumb is the ID.
  • The title is the record's name, or its ID when it has none.
  • Labels are the field's name in sentence case ("First reported at"). Dates read "15 Nov 18:52", with the year when it is not this year.
  • Points here reads "{table} as {field}": "Listing report entries as report".
  • Create says "New member" and "Create member"; edit says "Save changes"; the toast after deleting says "{n} {things} deleted" with Undo.
