Skeleton

Skeletons stand in for content while a page loads, in the shape of what is coming: business cards, request rows, message threads, forms. They shimmer gently, hide from assistive technology, and a single status sentence says what is loading.

Overview

Use skeletons for the first load of a page or region whose layout is known. Keep real chrome (top bar, page title, tabs, search) and replace only the data. Use a Spinner for an action the person started, and an Empty state once the load returns nothing.

  • Text lines (.skeleton--text, with --w30/50/70 widths); the last line in a group is 60%.
  • Title and H1 bars for headings.
  • Avatar, media (4:3) and square for images.
  • Rect for inputs and panels; button (.skeleton--btn, --btn-sm) for pill actions.

Anatomy

  1. Media.skeleton--media: 4:3, --radius-lg, the card's photo.
  2. Title line.skeleton--text.skeleton--w70: the business name.
  3. Meta line.skeleton--text: full width, the category and area.
  4. Short line.skeleton--w50: the rating or price.

Sizes

Shapes take their size from the content they replace: text lines follow the font size (0.9em high), titles 1.5em, H1 --font-size-4xl, avatar --avatar-size-md, button --control-height-md. Width modifiers are 30, 50 and 70%; vary them so the block reads as text, not as a barcode.

States

Skeletons are not interactive: no hover, focus, active or disabled. They have two states, loading and reduced motion, and then they are replaced.

ShapeLoading (shimmer)Reduced motion (static)
Text block

Both themes

  • Replace the whole skeleton region at once when data arrives; do not fill it card by card.
  • If loading fails, swap the skeleton for an error empty state in the same place.
  • Show at most one screen's worth: four cards, six rows.

Responsive behaviour

  • Skeletons sit inside the real layout (.card-grid, .rows, .inbox), so they reflow exactly like the content: four cards per row on desktop, one on phones.
  • Percent widths scale with the container; fixed shapes (avatar, button) do not.

Theming

The shimmer is a gradient between --color-bg-subtle and --color-bg-subtle-hover, which are ink-100/200 in light and ink-800/700 in dark. No other colour is involved.

Accessibility

Role and pattern

Skeleton containers carry aria-hidden="true". One visually hidden <p class="visually-hidden" role="status">Loading the directory…</p> per region announces the load; it changes to the result count or is removed when the content arrives. Set aria-busy="true" on the region while it loads. See the APG feed pattern for aria-busy use and WCAG 4.1.3.

Keyboard

KeyAction
NoneNothing to focus. Real controls on the page (search, tabs) stay usable while content loads.

Focus

Focus is not moved into a loading region. When content arrives, focus stays where the person left it.

Labelling

The status sentence names what is loading: "Loading conversations…", "Loading the directory…".

Motion

Shimmer loops over --duration-loop. Under reduced motion it stops and the shapes stay flat.

Touch

Not interactive.

Content

  • Skeletons have no text. The status line says "Loading thing…", and the page subtitle can say the same ("Loading conversations…").
  • Keep the real page title and tab labels; only data is skeletal.
