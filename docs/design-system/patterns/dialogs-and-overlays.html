Pattern

Dialogs and overlays

An overlay borrows the member’s attention. Jubilee uses one only to finish a small task in place or to confirm something that is hard to undo, and always gives the attention back where it was.

Overview

The mocks hold 21 dialogs. They fall into four kinds, all built on the Dialog: request dialogs that send something to a business (Book a meeting, Request a quote, Request an item, New message), answer dialogs for a business owner (Confirm request, Decline request), editors (Product editor, Service editor) and confirmations (Cancel request, Delete product, Pause listing, Sign out, Delete account, Take down listing). Lighter overlays are the Menu, Drawer, Popover and Tooltip.

  • One question per dialog. The title is that question or task: "Decline Samuel’s order?", "Book a meeting with Legacy Financial".
  • The footer is always the same: the safe action first, the committing action last and named for what it does.
  • Danger is earned. The red button appears only in confirmations of loss; Delete account also asks the member to type DELETE.
  • Below 640px a dialog is a bottom sheet with the same parts; the user menu and filters become sheets too.

Structure

A dialog has a header (optional status icon, title, description, close), a body and a sticky footer. The description is referenced by aria-describedby; the panel sits on a backdrop.

PartRule
Icon.dialog__icon--info for requests and neutral confirmations, --danger for loss, --success for a done state. Decorative: aria-hidden.
Title<h2 class="dialog__title"> with an id used by aria-labelledby. A question for confirmations, a task for forms.
DescriptionOne or two sentences of consequence, id used by aria-describedby.
CloseGhost icon button, aria-label="Close", top right. Same effect as Esc and the safe action.

Responsive behaviour

  • Below 640px (--layout-breakpoint-sm) .dialog aligns its panel to the bottom edge, rounds only the top corners and slides up; from 640px it centres and scales in.
  • The panel is capped at the viewport height minus --space-12 and scrolls inside; the footer stays visible (sticky) so the commit is never off screen with the keyboard open.
  • The account menu is a sheet on phones and an anchored menu from 640px; Filters is a sheet below 768px and inline chips above.
  • Footer buttons wrap and the commit stays last; on a 360px sheet two medium buttons fit on one row.

Accessibility

Pattern and roles

Dialogs follow the APG modal dialog pattern: role="dialog", aria-modal="true", aria-labelledby to the title, aria-describedby to the description. The page behind is inert. Menus follow the APG menu button pattern; tooltips the APG tooltip pattern.

Keyboard

KeyAction
Tab / Shift+TabCycle inside the dialog only (focus trap).
EscCloses the dialog as the safe action would (data-dismiss-on-escape), except while busy. In a menu, closes the menu.
EnterActivates the focused button; in a single-field dialog it submits.
↑ ↓ in a menuMove between items; Home/End jump; typing a letter jumps to the item.

Focus

On open, focus goes to the first field in a form dialog, to the safe action in a destructive confirmation ("Keep request", "Keep my account") and to the primary in a success view (autofocus in the mocks). On close, focus returns to the control that opened it, or to the row that replaced it if that control is gone.

Labelling and announcements

The title names the object ("Cancel your quote request to WaterWorks?"); the close button is "Close"; danger commits name the loss ("Delete account"). The backdrop is not a control and has no label.

Motion

Backdrop fades and the panel scales or slides in over --duration-base with --ease-enter; under reduced motion durations are zero and the dialog simply appears.

Touch

Close and footer buttons are 44px. A bottom sheet keeps its footer above the home indicator (env(safe-area-inset-bottom)). Menu items in the account sheet are 44px tall.

Content

  • Confirmation titles are questions with the object: "Delete Faith heavyweight tee, charcoal?", "Sign out of Jubilee?".
  • The description states the consequence and who is told: "WaterWorks Plumbing & Drains is told straight away. You can ask again later."
  • The safe action says what is kept: "Keep request", "Keep my account", "Stay signed in", "Not yet". Use "Cancel" only when nothing is being kept.
  • Request dialogs remind that nothing is paid on Jubilee: "Ask for a time. Trevor confirms it or suggests another; nothing is charged."
  • Irreversible actions list what goes, as bullets, and end with "This can’t be undone."

Drift found: every dialog wraps its title in <div style="flex: 1;"> and gives the description style="margin-top: var(--space-1)" inline (68 dialogs); a .dialog__heading rule would remove both (suggested in the report). Time chips in Book a meeting are <label class="chip" style="position: relative"> around visually hidden radios; the system documents them as a radio group styled as chips. Menu items in the user-menu sheet set min-height inline to reach 44px. The menu, drawer, popover and tooltip components exist in the kit but no mock renders them open.
