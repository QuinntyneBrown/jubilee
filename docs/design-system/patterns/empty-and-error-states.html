Pattern

Empty and error states

An empty or broken screen is still a step in someone’s task. Jubilee always says why it is empty, reassures that nothing is lost, and offers the next action.

WCAG 2.2 AAPattern

Overview

Every list and every page in the mocks has an empty and an error state. They share one layout, the Empty state (.empty: icon, title, text, actions), and differ in icon colour, size and copy. Whole-page failures use the Error page layout (.status-page) with the same parts.

  • First use (nothing yet): invite the first action. "Book, ask or order to get started."
  • No results (search or filter matched nothing): show the query, suggest a correction, offer a wider route.
  • Filtered to nothing (a tab with zero items): compact, one way back: "No declined requests · Show all requests".
  • Load error: .empty--error, "Nothing is lost", a support code (JB-DIR-503) and Try again.
  • Whole-app conditions: not found, no access, something went wrong, offline, session expired and maintenance each have a full page.

Responsive behaviour

  • The empty layout is centred and its text capped at 36ch at every width, so it reads the same on a phone and a 1280px screen.
  • Actions wrap and centre; on phones two actions stack with the primary first.
  • Inside cards, panels and the inbox list use .empty--compact (32px top and bottom instead of 48px).
  • Full-page states keep the top bar and phone tab bar; .status-page centres in 70% of the viewport height so the message is above the fold on a 360 × 640 phone.

Accessibility

Pattern and roles

An empty state is plain content: a heading, a paragraph and links or buttons. A load error that replaces content after the page rendered carries role="alert" so it is announced (APG alert pattern). Icons are aria-hidden.

Keyboard

KeyAction
TabReaches the inline suggestion link, then the actions, in reading order.
EnterFollows the action. Try again reloads only the failed region where possible.

Focus

After Try again succeeds, focus goes to the first item of the reloaded region, or stays on the region heading. On a full-page error the h1 is the first thing after the skip link.

Labelling and announcements

The title is a real heading at the right level for the page outline (h1 on a status page, h2 under a page header, h3 inside a card). Support codes are in <code> so they are read character by character.

Motion

Empty and error states appear without animation; nothing bounces or pulses to draw attention.

Touch

Actions are medium buttons (44px). The inline suggestion link sits in a sentence, so its target is its line height, which the 24px spacing exception covers.

Content

  • Title: what is true now, in plain words. "We can’t find that page", "Nothing matches “plumbre”", "You’re all caught up". Never "Error 404" or "No data".
  • Text: why, then what to do. Errors start with "Nothing is lost." when that is true, and end with a support code: "If it keeps happening, tell us and quote JB-LST-503."
  • Codes follow JB- + area + status: JB-AUTH-503, JB-REQ-502, JB-DIR-503.
  • Actions are verbs that move forward: "Browse businesses", "Search “plumber”", "Try again". "Back to browse" is the escape, never the only action on a first-use state.
  • No-results repeats the member’s words in curly quotes and offers the correction as a link.
